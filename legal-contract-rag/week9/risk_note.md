1. **Who wrote it:** the knowledge team, not us. It is vendored at `vendor/contract-repository-mcp/` (in this repo, a stand-in written to their interface) with no signed release and no pinned upstream version, so we run whatever is in that folder through `npx tsx`, as our own OS user, inside the agent's trust boundary.
2. **What it can reach:** every `.txt` under `CONTRACT_REPO_DIR`, which is all 13 executed documents, including SA-2026-001 with its §6 confidentiality clause, with no per-contract access control. Its code reads only that directory, but nothing confines it there: an unsandboxed local process can read any file our user can and can open the network, and `readOnlyHint` is a claim it makes about itself, not enforcement. It does not get our Gemini or Qdrant keys, only PATH/HOME/SHELL/TERM/USER/LOGNAME plus the two variables our config passes.
3. **What it logs:** one plaintext line per `tools/call` (timestamp, tool, full arguments such as contract ids and dates, ok/error) to `logs/contract-repository.log`, never rotated or redacted. It cannot log *who* asked, because every call arrives under the one service token, so its log cannot answer "who read the confidential contract?"
4. **What a stolen token could do:** `CONTRACT_REPO_TOKEN` is one long-lived, unscoped token that reads every executed contract, including those under NDA. There are no write tools, so the loss is confidentiality, not tampering. The token sits in the host's environment, where any process of our user, and any other MCP server we pass `${CONTRACT_REPO_TOKEN}` to, can read it.
5. **Ship or don't:** ship for Thursday only behind the gateway (`mcp.frontdoor.json`: per-caller tokens and one audit line per call with caller and contract id). Don't wire it in directly with the all-contracts token. And before it serves NDA contracts, get a repository token scoped to the contracts under review, because tool scopes don't contain data: a caller denied `get_amendment_chain` can still read the same amendment text through our own `find_amendments`.
